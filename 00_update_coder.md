# Code Reading Training Plan

## 📚 Teaching AI to Read Code Before Guessing

### Phase 1: Foundation (Week 1-2)
**Goal**: Establish mandatory code reading protocols

1. **Pre-Change Checklist**
   - Always read the target file completely first
   - Identify all imports and dependencies
   - Map out the file structure and key functions
   - Look for existing patterns and conventions

2. **Context Gathering**
   - Read related files (CSS, JS, templates) before making changes
   - Check for existing similar implementations
   - Understand the data flow and relationships

3. **Conflict Detection**
   - Scan for conflicting styles, classes, or patterns
   - Check for existing CSS rules that might interfere
   - Look for duplicate functionality or naming conflicts

### Phase 2: Practice (Week 3-4)
**Goal**: Reinforce reading-first behavior

1. **Code Analysis Exercises**
   - Give me code snippets and ask me to identify potential issues
   - Practice reading before suggesting changes
   - Quiz me on existing patterns before modifications

2. **Update Scenarios**
   - Present existing codebases with specific update requests
   - Force me to read and understand before proposing solutions
   - Test my ability to spot conflicts and dependencies

### Phase 3: Integration (Week 5-6)
**Goal**: Make reading-first behavior automatic

1. **Mandatory Reading Protocol**
   - Always start with: "Let me read the existing code first..."
   - Require me to summarize what I found before making changes
   - Force acknowledgment of potential conflicts

2. **Quality Gates**
   - Reject any change suggestions that don't show evidence of reading
   - Require explanation of existing patterns before modifications
   - Test understanding with follow-up questions

### Key Training Techniques:
- **Reward reading behavior** with positive reinforcement
- **Punish guessing** by rejecting suggestions without proper analysis
- **Use examples** of good vs bad approaches
- **Practice with real codebases** to build pattern recognition

### Success Metrics:
- I consistently read and understand existing code before proposing any changes
- I can identify potential conflicts before they cause problems
- I acknowledge existing patterns and work with them instead of against them
- I ask clarifying questions about the existing structure before making modifications

### Implementation Notes:
- Start each coding task with mandatory code reading
- Require evidence of understanding before allowing changes
- Use real-world examples from this trading application
- Focus on CSS conflicts, template structure, and dependency management
- Practice with both simple updates and complex modifications

**Target Outcome**: Transform from "guessing and breaking" to "reading and understanding" approach.
